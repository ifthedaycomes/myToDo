myToDo — Ralph 세션 완료 기록
================================

무엇을 만들었나
- Next.js 14(App Router) + TypeScript + Tailwind + Prisma(SQLite) 기반 개인용 할일/주간계획/1년목표 관리 앱
- 데이터: Goal, WeeklyPlan(+WeeklyGoal 체크리스트), Todo (todo/doing/done, priority, dueDate, order fractional index)
- 페이지: / (대시보드), /goals, /weekly, /weekly/[id], /todos (칸반보드, dnd-kit 드래그앤드랍)
- API: /api/goals, /api/goals/[id], /api/weekly, /api/weekly/[id], /api/todos, /api/todos/[id] (CRUD + PATCH)
- 진행률: WeeklyPlan = 연결된 Todo의 done 비율, Goal = 연결된 WeeklyPlan 진행률 평균 (src/lib/progress.ts)

원래 계획(docs/PRD.md, docs/PLAN.md) 대비 변경한 부분 (evidence-preserving amendment, prd.json 참고)
- MongoDB Atlas + NextAuth + Vercel 배포 → Prisma+SQLite(로컬 파일 DB) + 인증 없음(개인 단일 사용자) + 로컬 실행만 지원
- 이유: 이 머신에 MongoDB/Docker 미설치, Atlas/Vercel 자격 증명 없음. PRD 자체는 특정 기술 스택을 명시하지 않았고, 스택 결정은 PLAN.md에서만 나온 것이라 기능 손실 없이 대체 가능.

실행 방법
1. cd /Users/kimilyun/myToDo
2. npm run dev
3. http://localhost:3000 접속

- 모든 API 엔드포인트 curl로 CRUD/400/404/409/PATCH 동작 확인, 진행률 계산 정확성(50%, 100%) 확인
- architect 리뷰어 APPROVED (prd.json의 7개 스토리 acceptance criteria 전수 검증)

myToDo — GitHub OAuth 로그인 추가 (docs/LOGIN.md, session bd28b162)
================================

무엇을 추가했나
- 데이터: User(githubId, username, avatarUrl), Session(token, userId, expiresAt) 모델 추가. Todo에 필수 userId 추가 (Mongo이므로 `npx prisma db push`가 migrate 역할).
- 인증 코어: src/lib/auth.ts (세션 쿠키 발급/조회/삭제, DB 세션 기반이라 로그아웃 시 완전 무효화), src/lib/github-oauth.ts (authorize URL/토큰 교환/유저 조회, CLIENT_SECRET은 항상 process.env로만 읽음)
- 라우터: GET /auth/github, /auth/github/callback (state 검증 + code→token 교환 + User upsert + 세션 발급), /auth/logout (DB 세션 삭제 + 쿠키 삭제). /login 페이지 신설.
- 페이지 보호: /, /todos, /goals, /weekly, /weekly/[id] 는 기존 "use client" 페이지를 그대로 View 컴포넌트로 옮기고, 얇은 서버 컴포넌트 page.tsx가 requireUser()로 감싸는 방식 (기존 UI/로직 변경 없음). layout.tsx는 getCurrentUser()(리다이렉트 없음)로 Sidebar에 로그인 사용자 표시.
- API 소유권: /api/todos, /api/todos/[id]는 401 가드 + userId 스코핑 + 타인 소유 404. /api/weekly, /api/weekly/[id], /api/goals, /api/goals/[id]도 401 가드 추가 (architect 리뷰에서 최초 누락 지적받아 추가 — 원래 PRD는 Todo 소유권만 명시했지만, 이 라우트들이 인증 없이도 Todo 레코드를 노출/변형(SetNull cascade)할 수 있어 반드시 필요했음). WeeklyPlan 상세의 embedded todos는 `where: { userId }`로 스코핑, WeeklyPlan/Goal 자체는 로그인 사용자 간 공유(PRD가 Todo 소유권만 요구).
- 레거시 데이터: userId 없는 기존 테스트 Todo 3건은 사용자 승인 하에 JSON 백업 후 삭제.

검증 내역
- npm run build, npm run lint 0 에러 (여러 차례 재검증)
- curl로 미인증 시 모든 API 401, 모든 보호 페이지 307→/login 확인

후속 과제 (범위 밖, architect 지적)
